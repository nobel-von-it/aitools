# Участие в разработке

Спасибо за интерес к проекту. Ниже описаны локальные проверки и правила, которые помогают держать репозиторий в рабочем состоянии.

## Требования

- Rust 1.85 или новее (edition 2024).
- `rustfmt` и `clippy` (устанавливаются через `rustup component add rustfmt clippy`).
- Для проверки песочницы MCP: `bwrap` и Linux.
- Для OCR через Tesseract: системный бинарник `tesseract`.
- Для OCR через `ocrs`: ONNX-модели, пути к которым задаются переменными окружения.

## Локальная проверка

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo doc --no-deps --all-features
```

Или одной командой:

```bash
make check
```

## Стиль кода

- Форматирование задаётся `rustfmt.toml`, проверка обязательна.
- Предупреждения `clippy` считаются ошибками в CI.
- Публичные типы и функции должны иметь документационные комментарии.
- Новые форматы добавляются через реализацию `Extractor`, а не через ветвления в CLI или MCP.
- Ошибки разбора не должны терять уже извлечённые данные: используйте `Warning`.
- Для новых источников данных проверяйте лимиты `Limits`.

## Коммиты

Используется формат Conventional Commits:

```text
feat: add spreadsheet sheet metadata
fix(pdf): handle empty text layer
docs: describe MCP grants
test(mcp): cover path escape attempts
chore: update CI actions
```

Допустимые типы: `feat`, `fix`, `docs`, `test`, `refactor`, `perf`, `chore`, `build`, `ci`.

Коммит должен быть атомарным: одно логическое изменение и связанные с ним тесты или документация.

## Изменения в MCP и песочнице

MCP-сервер имеет доступ к файловой системе, поэтому к изменениям в этой части предъявляются дополнительные требования:

- Любой путь из аргументов инструмента должен каноникализоваться и проверяться на вхождение в `root` или активный грант.
- Нельзя включать base64-инструменты по умолчанию в песочнице: это обход проверки пути.
- `request_access` не должен разрешать весь `grant_base` или предков `root`.
- Новые гранты обязаны оставаться в пределах проекта и не должны быть видны серверам из других проектов.
- Для изменений в launcher'е или проверке путей добавьте тест на попытку выхода за границу.

## Pull request

Перед отправкой:

1. Выполните `make check`.
2. Добавьте тест на новое поведение или объясните, почему он не нужен.
3. Обновите `README.md` и `CHANGELOG.md`, если меняется пользовательский интерфейс.
4. Убедитесь, что в diff нет секретов, абсолютных путей пользователя и сгенерированных файлов.

Шаблон pull request находится в `.github/PULL_REQUEST_TEMPLATE.md`.
